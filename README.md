# مركز شباب العبور — نظام إدارة النشاط الرياضي

## أهم تغيير: البيانات لا تعود مرتبطة بملفات GitHub
من الآن فصاعداً **لا يتم استخدام `db.json` الموجود داخل مجلد المشروع كقاعدة البيانات الحية**.

- في Windows عند تشغيل `run-app.bat`: البيانات تحفظ تلقائياً خارج المشروع داخل:
  `%LOCALAPPDATA%\ObourYouthClub\data\db.json`
- النسخ الاحتياطية التلقائية تحفظ خارج المشروع داخل:
  `%LOCALAPPDATA%\ObourYouthClub\backups\`
- إذا حذفت أو استبدلت ملفات المشروع من GitHub ثم حملت نسخة جديدة، **بيانات اللاعبين والحضور والاشتراكات والحسابات لا تُحذف** طالما أنك تستخدم نفس مجلد البيانات.
- عند أول تشغيل للنسخة الجديدة، إذا لم توجد قاعدة بيانات خارجية، يتم نقل/نسخ `db.json` القديم الموجود داخل المشروع إلى مخزن البيانات الدائم مرة واحدة فقط.

### عند النشر على Railway أو أي استضافة مشابهة
GitHub يجب أن يحتوي على **الكود فقط**، وليس بيانات التشغيل.

1. أنشئ Persistent Volume / Disk في الاستضافة.
2. اربطه بالمسار `/data`.
3. ضع متغير البيئة:
   `DATA_DIR=/data`
4. ويمكن وضع:
   `BACKUP_DIR=/data/backups`
5. بعد ذلك يمكنك عمل Deploy من GitHub متى شئت؛ البيانات الموجودة على الـ Volume لا تُستبدل مع تحديث الكود.

> إذا كنت تستخدم GitHub Pages فقط، فلن يعمل `server.js` وقاعدة البيانات المحلية أصلاً؛ يجب استخدام استضافة Backend مثل Railway/Render/VPS مع تخزين دائم.

## حماية البيانات
- حفظ ذري للبيانات لمنع تلف الملف عند انقطاع الكهرباء أثناء الكتابة.
- Backup تلقائي عند عمليات الحفظ المهمة.
- الاحتفاظ بآخر 30 نسخة احتياطية.
- زر Backup يدوي من داخل لوحة الإدارة.
- إذا وجد `db.json` تالفاً، يتم حفظ نسخة منه باسم `.broken-...json` قبل إنشاء قاعدة فارغة.
- ملفات البيانات والنسخ الاحتياطية مستبعدة من Git عبر `.gitignore`.

## المزايا الحالية
- RTL كامل وخط عربي واضح.
- نسخ احتياطي يدوي وتلقائي.
- طباعة التقارير مع `@media print`.
- حضور وغياب حسب التاريخ.
- تنبيهات الاشتراكات المنتهية وتلوين اللاعبين غير المسددين.
- أرشيف تلقائي بعد يوم 5 من كل شهر.
- حسابات مشاهدة + تعديل مقيدة بالرياضات المسموح بها.
- اختيار أكثر من رياضة للحساب.
- أنواع العضوية الثلاثة فقط.
- الرقم القومي للاعب.
- Excel import/export.
- صور اللاعبين والإيصالات.
- PWA وOffline caching.
- معالجة أخطاء الخادم.
- جلسة مستمرة أثناء الاستخدام مع heartbeat.
- Responsive وتصميم RTL وتحديث ديناميكي.

## التشغيل المحلي
1. ثبّت Node.js LTS.
2. شغّل `run-app.bat`.
3. أو من الطرفية:
```bash
npm install
set DATA_DIR=%LOCALAPPDATA%\ObourYouthClub\data
set BACKUP_DIR=%LOCALAPPDATA%\ObourYouthClub\backups
npm start
```
4. افتح `http://localhost:3000`.

## بيانات الدخول الافتراضية
- الأدمن: `Fasmo`
- كلمة المرور: `Fasmo123#`

يفضل تغييرها في الإنتاج باستخدام `ADMIN_USER` و`ADMIN_PASS`.

## تحديث المشروع من GitHub بدون فقد البيانات
**لا تضع `db.json` الفعلي في GitHub.**
عند تحديث الكود، ارفع ملفات المشروع فقط. البيانات تبقى في `DATA_DIR`.

إذا كنت تستخدم Railway: تأكد أن الـ Persistent Volume موجود ومركب على `/data` قبل كل Deploy.

## PWA احترافية
- التطبيق قابل للتثبيت على Android وiPhone/iPad وWindows/macOS من المتصفح.
- يوجد `manifest.webmanifest` متكامل، أيقونات متعددة الأحجام، اختصارات للتطبيق، وواجهة RTL.
- يوجد Service Worker بإستراتيجية Network First للصفحات وStale-While-Revalidate للأصول، مع صفحة Offline عند انقطاع الإنترنت.
- عند توفر إصدار جديد يظهر تنبيه داخل التطبيق لتحديث النسخة بدون الحاجة لإعادة تثبيت التطبيق.
- لا يتم تخزين استجابات `/api/*` داخل Service Worker حتى لا تصبح البيانات القديمة هي مصدر الحقيقة.
- **مهم:** Offline هنا مخصص لواجهة التطبيق؛ عمليات اللاعبين والحضور والاشتراكات تحتاج اتصالًا بالخادم وقاعدة البيانات الدائمة.

### تثبيت التطبيق
1. افتح الموقع من Chrome/Edge على الهاتف أو الكمبيوتر.
2. استخدم زر التثبيت الذي يظهر داخل الموقع أو خيار **Install app / إضافة إلى الشاشة الرئيسية** من قائمة المتصفح.
3. على iPhone/iPad استخدم Safari ثم **مشاركة → إضافة إلى الشاشة الرئيسية**.

### الاستضافة والبيانات
إذا كان المشروع منشورًا على Railway أو أي استضافة تعتمد على حاويات مؤقتة، اربط Persistent Volume واجعل `DATA_DIR=/data`. GitHub يبقى للكود فقط، أما بيانات النادي فتبقى على التخزين الدائم.
